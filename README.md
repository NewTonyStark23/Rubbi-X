# 🏛️ Core Architecture

## The R1/R2 Nested System

Rubbi-X uses a **nested architecture** with two types of Graphify instances:

### R1 — The Persistent Core

**Purpose:** Master Graphify map for the project  
**Lifecycle:** Lives forever (until user deletes it)  
**Memory:** Accumulates atomic notes from all R2 instances  
**Backup:** Auto-backs up after every resolution  

**What R1 contains:**
- Project architecture map (6 dimensions)
- All successful resolution patterns
- All failed approaches (as negative weights)
- Atomic notes from every R2 instance
- Backup history

**Key properties:**
- ✅ Never requires user reminder to backup
- ✅ Survives across sessions
- ✅ Grows smarter with every resolution
- ✅ Auto-prompts user at session end: "Keep R1? [Y/n]"

### R2 — The Ephemeral Solver

**Purpose:** Solve specific sub-problems  
**Lifecycle:** Spawns → solves → merges to R1 → **deletes itself**  
**Memory:** Writes atomic notes during resolution  
**Cleanup:** Automatically deletes to free context window space  

**What R2 does:**
1. Spawns when a problem arises
2. Decomposes problem into 6 dimensions
3. Applies 10 advanced strategies
4. Writes atomic notes for every step
5. Detects loops via path hashing
6. Injects Superpowers when deadlocked
7. Converges on solution
8. Merges successful notes to R1
9. **Deletes itself** to free space

**Key properties:**
- ✅ Independent from R1 (doesn't pollute main memory)
- ✅ Uses all 10 strategies
- ✅ Writes immutable atomic notes
- ✅ Self-destructs after merging

## The Lifecycle

```
1. User submits problem
   ↓
2. R1 loads (or creates new)
   ↓
3. R2 spawns for this specific problem
   ↓
4. R2 decomposes into 6 dimensions (Graphify cube)
   ↓
5. R2 applies strategies, writes atomic notes

    ↓

    ↓

```

#### 1. Resolution Confidence Index (RCI)

**Deterministic:** ✅ Yes  

**Example calculation:**
```

pattern_match = 0.78 (from PatternRecognitionEngine)

RCI = 0.34 + 0.234 + 0.27
RCI = 0.844 → 84.4%
```

#### 2. Pattern Match Confidence (PMC)
**Description:** Confidence that current problem matches a known pattern  
**Formula:** `PMC = (structural_similarity × 0.5) + (causal_similarity × 0.3) + (temporal_similarity × 0.2)`  
**Deterministic:** ✅ Yes  

**Example calculation:**
```

causal_similarity = 0.88 (from causal chain analysis)

PMC = (0.92 × 0.5) + (0.88 × 0.3) + (0.85 × 0.2)
PMC = 0.46 + 0.264 + 0.17
PMC = 0.894 → 89.4%
```

#### 3. Deterministic Path Score (DPS)
**Description:** Reproducibility score — how likely this path will succeed again  
**Formula:** `DPS = (historical_success × 0.6) + (context_similarity × 0.4)`  
**Deterministic:** ✅ Yes  

**Example calculation:**
```

context_similarity = 0.75 (current context is 75% similar)

DPS = (1.0 × 0.6) + (0.75 × 0.4)

```

**Description:** Speedup achieved via GPU parallel processing  
**Formula:** `GAF = (cpu_time / gpu_time) × parallelism_efficiency`

#### 5. Loop Prediction Accuracy (LPA)

**Deterministic:** ✅ Yes  

**Example calculation:**

#### 6. Atomic Note Integrity (ANI)

**Formula:** `ANI = (valid_notes / total_notes) × 100`  
**Deterministic:** ✅ Yes

# 🎲 Deterministic Complexity Engine

**"The Big Guns" Activation System — Always Hold the High Cards**

## The Core Concept

**Problem Complexity → Feature Activation**

```
Simple Problem    → Tier 1: Basic loop detection only (~70ms overhead)
Medium Problem    → Tier 2: + Model Detection + Pattern Recognition (~250ms overhead)
Complex Problem   → Tier 3: + Context Optimizer + Multi-Agent Layer (~450ms overhead)
Ultra-Complex     → Tier 4: All features + GPU acceleration (~600ms overhead)
```

**The system deterministically classifies complexity BEFORE processing, then activates only the features needed.**

## Deterministic Complexity Scoring

**6 deterministic metrics** combine into a single complexity score (0-100):

### Metric 1: Token Complexity (TC)
**What:** How many tokens is the problem?  
**Formula:** `TC = min(100, (token_count / 1000) * 100)`  
**Weight:** 15%  

**Examples:**
- "What's 2+2?" → 4 tokens → TC = 0.4
- "Fix this React bug" → 200 tokens → TC = 20
- "Design a distributed system" → 2000 tokens → TC = 100

### Metric 2: Entity Density (ED)
**What:** How many distinct entities/concepts in the problem?  
**Formula:** `ED = min(100, (entity_count / 20) * 100)`  
**Weight:** 20%  

**Examples:**
- "What's 2+2?" → 2 entities (2, 2) → ED = 10
- "Fix this React bug" → 5 entities (React, component, state, useEffect, bug) → ED = 25
- "Design a distributed system" → 15 entities → ED = 75

### Metric 3: Dependency Depth (DD)
**What:** How deep is the dependency graph?  
**Formula:** `DD = min(100, (max_dependency_depth / 10) * 100)`  
**Weight:** 25% (highest weight)  

**Examples:**
- "What's 2+2?" → 0 depth → DD = 0
- "Fix this React bug" → 2 depth → DD = 20
- "Design a distributed system" → 8 depth → DD = 80

### Metric 4: Ambiguity Score (AS)
**What:** How ambiguous is the problem?  
**Formula:** `AS = (ambiguous_terms / total_terms) * 100`  
**Weight:** 10%  

**Examples:**
- "What's 2+2?" → 0 ambiguous terms → AS = 0
- "Fix this bug" → 1 ambiguous term ("this") → AS = 20
- "Optimize the system" → 2 ambiguous terms → AS = 40

### Metric 5: Domain Specificity (DS)
**What:** How specialized is the domain?  
**Formula:** `DS = (specialized_terms / total_terms) * 100`  
**Weight:** 15%  

**Examples:**
- "What's 2+2?" → 0 specialized terms → DS = 0
- "Fix this React bug" → 3 specialized terms → DS = 30
- "Design a distributed system" → 10 specialized terms → DS = 60

### Metric 6: Historical Resolution Time (HRT)
**What:** How long did similar problems take to resolve?  
**Formula:** `HRT = min(100, (avg_resolution_time / 60) * 100)`  
**Weight:** 15%  

**Examples:**
- "What's 2+2?" → 0.5s average → HRT = 0.8
- "Fix this React bug" → 15s average → HRT = 25
- "Design a distributed system" → 180s average → HRT = 100

## The Complexity Score Formula

**Final Complexity Score (CS):**

```
CS = (TC × 0.15) + (ED × 0.20) + (DD × 0.25) + (AS × 0.10) + (DS × 0.15) + (HRT × 0.15)
```

**Result:** Single score 0-100 that deterministically classifies problem complexity.

   ```python
   # Spawn R2 for a sub-problem
   r2 = middleware.spawn_r2("Fix useEffect loop")
   
   # Write atomic note
   from FORM_B_MIDDLEWARE import AtomicNote, NoteResult
   note = AtomicNote(
       id="note-1",
       timestamp=time.time(),
       node_id="node-0",
       action="Try approach A",
       result=NoteResult.SUCCESS,
       observation="Approach A worked",
       lesson="Use useRef for state",
       path_hash="abc123",
       dimension="structural",
       blocked=False,
       confidence_score=95.0
   )
   middleware.write_atomic_note(r2, note)
   
   # Check for loops
   loop_check = middleware.check_loop(r2, "node-0", "try approach B", "context")
   print(loop_check)
   
   # Merge R2 to R1
   middleware.merge_r2_to_r1(r2.id)
   
   # Get end-of-session prompt
   print(middleware.get_end_of_session_prompt())
   ```

### What It Does

- Creates SQLite database (`rubbix_my_project.db`)
- Manages R1 (persistent) and R2 (ephemeral) instances
